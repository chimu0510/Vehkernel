# 行式板級定義、依「選擇時機」決定多型形式的 HAL

**板級定義**

- 採仿 ArduPilot `hwdef.dat` 的行式描述語言：一行一個腳位，寫腳位、角色名稱與周邊，另外描述板上裝置及其安裝方向。
- 腳位配置本質上是一張平的表格，必須能與原理圖、資料手冊逐行比對；行式格式也讓 diff、merge、grep 都只牽涉單一行。
- 產生器依 MCU 的 AF 表驗證腳位、推導 AF 編號、分配 DMA，並支援 `include` / `undef` 繼承。所有產生器只用 Python 標準函式庫。
- 板子在編譯時決定，一塊板子一個韌體檔。載具類型與 Frame 則在執行時用參數決定（ADR 0013）。外接裝置用參數指派連接埠的用途，例如 `SERIAL1_FUNCTION`；連接埠以板級定義宣告的邏輯名稱稱呼，不用周邊實例名稱（ADR 0011）。

**HAL 分層**

由上到下：模組層 → 驅動層 → 介面層 → 平台層，依賴方向只能往下。可以跳過驅動層直接使用介面層的能力，例如 Link 的傳輸用 UART、致動器控制用 `PwmOutput`；但任何一層都不能繞過介面層直接使用平台層。

分層之外有兩個共用部分：`core/`（匯流排、Work Queue、參數執行時）各層都可以依賴，它本身只依賴 FreeRTOS；`lib/` 的數學函式庫不依賴任何一層，也不依賴 `core/`（ADR 0014）。

多型的形式跟著「選擇在什麼時候做」：

- **平台周邊**：每次建置只有一種 MCU，所以用具體類別，再以 C++20 concept 檢查契約。STM32、SITL、單元測試靠建置配置切換實作，驅動不寫成樣板。
- **驅動與消費端之間**：不定義介面，透過匯流排解耦。
- **在執行時才選擇的部分**：Link 的傳輸與協議模組、載具模型與 Frame，用虛擬介面。

介面層保持精簡，只定義通用驅動需要的部分。計時器這類高度依賴平台的功能，以「能力」的形式提供，例如 `PwmOutput`、`QuadratureEncoder`。

平台層以 ST LL 為主，只在必要時（例如 USB）才用 HAL1。

## Considered Options

- **YAML 板級定義**：不採用。它用樹狀結構描述扁平的表格，篇幅膨脹、難以和原理圖逐行比對。（原本的另一個理由「需要第三方解析器」，在 ADR 0016 允許第三方套件後已不成立。）
- **平台層全部用虛擬介面（ArduPilot）**：不採用。一次建置只有一種平台，執行時多型沒有回報。
- **以 modm 作為平台層**：不採用。它會帶進自己的整套架構，綁定程度高。只借用它「錯誤的腳位用法在編譯時失敗」的想法，由我們自己的板級產生器產出有型別的腳位常數。
- **ST HAL2**：STM32F4 不在支援之列。

# 行式板級定義、依「選擇時機」決定多型形式的 HAL

**板級定義**

- 採仿 ArduPilot `hwdef.dat` 的行式描述語言：一行一個腳位，寫腳位、角色名稱與周邊，另外描述板上裝置及其安裝方向。
- 腳位配置本質上是一張平的表格，必須能與原理圖、資料手冊逐行比對；行式格式也讓 diff、merge、grep 都只牽涉單一行。
- 產生器依 MCU 的 AF 表驗證腳位、推導 AF 編號、分配 DMA，並支援 `include` / `undef` 繼承。所有產生器只用 Python 標準函式庫。
- 板子在編譯時決定，一塊板子一個韌體檔。載具與 Frame 則在執行時用參數決定。外接裝置用參數指派連接埠，例如 `UART3_FUNCTION`。

**HAL 分層**

由上到下：模組 → 裝置驅動 → L1 介面 → L0 平台實作，依賴方向只能往下，而且不能跳層。

多型的形式跟著「選擇在什麼時候做」：

- **平台周邊**：每次建置只有一種 MCU，所以用具體類別，再以 C++20 concept 檢查契約。STM32、SITL、單元測試靠建置配置切換實作，驅動不寫成樣板。
- **驅動與消費端之間**：不定義介面，透過匯流排解耦。
- **在執行時才選擇的部分**：Link 的傳輸與協議模組、運動學模型與 Frame，用虛擬介面。

L1 介面保持精簡，只定義通用驅動需要的部分。計時器這類高度依賴平台的功能，以「能力」的形式提供，例如 `PwmOutput`、`QuadratureEncoder`。

L0 以 ST LL 為主，只在必要時（例如 USB）才用 HAL1。

## Considered Options

- **YAML 板級定義**：不採用。它用樹狀結構描述扁平的表格，篇幅膨脹、難以和原理圖逐行比對，而且需要第三方解析器。
- **平台層全部用虛擬介面（ArduPilot）**：不採用。一次建置只有一種平台，執行時多型沒有回報。
- **以 modm 作為 L0**：不採用。它會帶進自己的整套架構，綁定程度高。只借用它「錯誤的腳位用法在編譯時失敗」的想法，由我們自己的板級產生器產出有型別的腳位常數。
- **ST HAL2**：STM32F4 不在支援之列。

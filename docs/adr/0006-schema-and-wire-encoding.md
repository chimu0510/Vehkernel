# Schema 採 .msg 風格，自訂協議採固定排列 little-endian 編碼

所有 Topic 用 ROS `.msg` 風格的 Schema 定義，可附加單位、頻率等擴充註解，這是唯一的定義來源。產生器據此產生 MCU 端結構體與編解碼、Bridge 的解碼與 ROS2 訊息轉換、工具端解析器、欄位文件，並為每個訊息算出 Schema 雜湊。連線握手時逐一比對雜湊，只要有任何一個不一致就拒絕連線，並回報是哪些訊息不同。協議本身的版本可以協商（ADR 0002），Schema 不行。

編碼格式屬於各個協議模組。自訂協議採固定排列的 little-endian：照 Schema 順序排列欄位，中間不補空白。內部結構體與線上格式分開，由產生器產生逐欄位的 `encode()` / `decode()`，不直接 `memcpy` 結構體。

## Considered Options

- **CDR**：只用在之後的 XRCE-DDS 協議模組，由同一份 Schema 產生。自訂協議不採用，因為對齊會浪費頻寬，對 MCU 也沒有額外好處。
- **varint / 欄位標籤式（protobuf 類）**：不採用。機器人資料以浮點數為主，省不了頻寬；它「跳過未知欄位」的相容性能力，已經由 Schema 雜湊取代。
- **直接 `memcpy` 結構體**：不採用。編譯器的補位方式因平台而異，內部結構體也會被協議綁死。

# 時序拆成可選的維度，不寫死成固定方案

主流韌體的時序設計各不相同：

- Betaflight：陀螺儀驅動，用 `pid_process_denom` 分頻。
- PX4：感測器發布後喚醒控制。
- ArduPilot：固定頻率主迴圈，由 `SCHED_LOOP_RATE` 加排程表決定，表中記錄每個任務的頻率、最長執行時間與優先級。

三者各有適用的硬體條件，所以我們把時序拆成四個可以獨立選擇的維度：

1. **觸發來源**：`IMU_EVENT`（資料就緒或 FIFO 水位中斷）或 `TIMER`（固定頻率）。
2. **基準頻率 + 分頻**：`CTRL_RATE_HZ` 是基準頻率，估測、角速度控制、速度與姿態控制各自設定分頻；定時的工作項目各自設定頻率。
3. **感測器取樣模式**：逐樣本讀取，或批次讀取 FIFO。驅動宣告最高 ODR 與每次讀取的匯流排成本，板級定義宣告匯流排類型。
4. **時序預設組**：預設值依 ADR 0012 分層取得，由板級定義提供，Frame 預設組可以覆寫。

開機時依驅動能力與匯流排成本估算 CPU 預算；設定不可行時，降到可行的最高頻率並發出警告。執行時監看每個工作項目的執行時間、抖動與超時次數，並發布到匯流排。

## Consequences

- C50C V1.1 只是其中一種組合。原廠韌體寫的是 SCL = PB9、SDA = PB8，但 F407 硬體 I2C1 的腳位是 PB8 = SCL、PB9 = SDA，所以板子很可能接反，只能用軟 I2C。一次 IMU 讀取約 135 個 SCL 週期，在 400 kHz 下約 0.34 ms，而且是 CPU 忙等，所以這塊板子的板級預設約為 200 Hz。換成以硬體 SPI 接 IMU 的板子，只要改板級預設值即可，架構不變。
- 實際接線要用 bring-up 測試確認：以軟 I2C 分別試兩種接法，讀 ICM20948 的 WHO_AM_I，正確值是 `0xEA`。

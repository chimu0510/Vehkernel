# 車頭方向由軟體定義，以 C50C 控制板設定為準

底盤的驅動端與全向輪端位置固定，車頭方向（驅動端在前／全向輪端在前）由軟體切換，不拆換馬達與輪子；切換時只把雷達與相機改裝到車頭那一端的感測器支架上。車頭方向的唯一正本存在 C50C 控制板的 Flash 設定中，開機時載入，不支援運行中切換：遙控行駛不依賴 Raspberry Pi 5，控制板必須自己知道車頭方向。Raspberry Pi 5 在連線時讀取控制板回報的車頭方向並與 ROS2 端設定比對，不一致時拒絕進入自主模式，因為兩邊不一致會讓「前進」變成後退、里程計方向相反。

## Consequences

- 差速運動學、輪距、輪徑不隨車頭方向改變；控制板只在運動學與馬達之間的映射層切換左右通道並反轉方向。
- IMU 隨控制板固定在底盤上，z 軸不受影響；x、y 軸的換算交給 ROS2 端的座標轉換，控制板若使用俯仰角則需參考車頭方向。
- URDF 以 xacro 參數描述車頭方向：`base_link` 固定在驅動軸中點、只隨車頭方向繞 z 軸轉 180°；兩端各定義一個感測器支架框架，雷達與相機相對車頭端支架定義，只寫一份。Nav2 footprint 由同一參數沿 x 軸鏡像產生。
- 雷達遮擋角度與感測器外參隨車頭方向各有一份；改裝後需重新驗證外參。
- 軟體無法偵測「設定已切換但感測器仍在舊端」，切換流程需由人確認感測器已改裝後才允許進入自主模式。

## Considered Options

- **以 Raspberry Pi 5 設定為準**：否決，遙控行駛時控制板會不知道車頭方向。
- **編譯期決定（原廠 `#if defined` 加 `robot.type` 的做法）**：否決，每次切換都要重新燒錄，且容易與 ROS2 端設定脫節。
